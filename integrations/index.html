Before choosing a connection

Start with what the team needs to happen.

Describe the handoff in plain language: where the information starts, where it should go, who checks it, and when it should stop.

01 / SourceWhich system actually supplies the data?

Name the provider, shop, account, and event that begins the handoff.

02 / FreshnessWhen was it last refreshed?

Show the source timestamp, awaiting connection state, and any errors instead of implying current data.

03 / CheckWho checks it before it moves?

Use a named role and say exactly what that person needs to confirm.

04 / StopWhich cases need a separate lane?

List missing repair orders, shop-code conflicts, duplicates, rejected drafts, provider errors, and unavailable feeds.

Connection questions

Confirm the connection before relying on it.

Are all represented systems native and live?

No. Tekmetric, CCC ONE, QuickBooks, Stripe, HighLevel, Google, Meta, GA4, and Search Console may be represented for architecture or planning. The available option and live state depend on the environment.

Does a setup record prove the feed is live?

No. Check the source, last refreshed time, awaiting connection state, and errors against the provider before relying on the feed.

What should we bring to the first discussion?

Bring the current steps, source system, provider access, destination, owner, last known refresh, common errors, and the result you need.
